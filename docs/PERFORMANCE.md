# 性能测量说明

本项目沿用 Electron + Vue。优化重点是封面、长列表和不必要的后台工作，而不是更换 UI 框架。

## 为什么简单应用也会占较多内存

Electron 包含 Chromium、Node.js 和多个辅助进程，GPU、解码、缓存也会占内存。原实现还存在额外开销：44px 封面直接使用几千像素原图，数百首列表全部渲染，展开播放器后有两份完整队列；使用歌曲 ID 加索引作为键会导致拖放后重建大量行。

当前实现按显示尺寸请求封面，只渲染视口附近的列表行，每个队列条目有独立稳定身份；缓存页面保留滚动位置，隐藏时暂停列表工作。进度变化只发送标量状态，磁盘写入异步串行执行。

## 优化阶段的历史对照

测量日期：2026-11-17。Windows、Electron 33.4.11、1080×720 CSS 像素、150% DPI、437 首合成歌曲，使用隔离应用数据目录。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 队列 DOM 行数 | 437 | 14 |
| 展开播放器后的 DOM 行数 | 874 | 15 |
| 跨350个位置拖放的提交时间（单次） | 23.5ms | 2.5ms |
| 缓存页面切换 p95（10次） | 43.3ms | 5.3ms |
| 快速滚动帧间隔 p95（89帧） | 50.0ms | 8.4ms |
| 解压后 Windows 分发目录 | 283.3MiB | 约229MiB |

真实公开封面地址的压力对照中，打开437首队列时，应用进程私有工作集合计约从1,524MiB降到332MiB。这个场景快速加载、遍历大量封面，不能当作一般使用的绝对占用。这里只报告一次本机样本，不提供跨机器保证，也不保证托盘后缓存立即归还系统。

从隐藏恢复到绘制的自动化延迟没有证明稳定变快；Alt-Tab 和托盘恢复的主观体验仍需按实际机器验证。优化后的 Electron 仍有固定成本。

上述数据来自 Electron 33.4.11。首次公开发布已升级到 Electron 45.3.3，历史体积与内存数值不能直接当作发布包的测量结果。

## 首次公开版复核

2026-11-17，在同一台 Windows 机器上使用 Electron 45.3.3 和隔离合成夹具复核：437 首队列渲染14行，展开播放器后共15行；一次跨350个位置拖放约2.3ms，10次缓存页面切换 p95 约3.7ms。真实 Chromium 跨视口拖动、边缘滚动、5,000首队列、增量保存及隐藏恢复检查通过。这些是自动化样本，不代表所有机器的体验。

另一次不截图的独立内存采样中，启动约242MiB、打开队列约303MiB，快速滚动后约426MiB，展开播放器约490MiB，隐藏后约490MiB（应用各进程私有工作集合计，四舍五入）。GPU进程与缓存占较大部分，隐藏没有立即释放这些内存。应用目前仍有用户最初关心的数百MiB占用，不能将交互优化描述为已经解决 Electron 的固定成本。长流程截图回归会增加GPU和截图缓冲开销，因此不使用该流程的峰值代替日常内存测量。

新运行时的 Windows x64 分发目录约309.6MiB，其中应用的 `app.asar` 约0.30MiB，没有附带 `node_modules`，语言包仅保留中文和英文。它比旧版 Electron 33 的精简包更大，不能沿用历史包体积作为本次发布的宣传数字。压缩后的安装包和便携版会小于解压目录，具体以 Releases 附件为准。

## 自己验证

在 Windows 中：

```powershell
npm ci
npm run build
npm run test:perf
```

脚本使用合成歌曲、封面和静音音频，不改真实播放器的数据。单轮总时限90秒，动作默认5秒。结果和截图写到被忽略的 `output/playwright/performance/`。

```powershell
node scripts/performance.cjs optimized-memory --memory-only
node scripts/package-size.cjs
```

内存采集使用 Windows 私有工作集，并保留 Electron 报告的各进程工作集与私有提交。它们不是同一个指标；比较时应保持队列、封面加载阶段、窗口状态与进程统计范围一致。脚本没有强制 GC、修剪工作集或禁用 GPU。

`--real-covers` 会只读本机用户状态中的公开封面 URL，再在隔离测试中请求 CDN；默认不启用。它依赖网络，可能触发上游限速。发布截图和自动检查使用合成夹具。

首次公开仓库保留当前源代码和测量摘要，旧的诊断输出、个人机器路径和开发前历史未发布。因此 `baseline-*` 比较模式需要使用者自行保存旧构建到脚本指定目录，不能直接从首次公开仓库复现历史版本。结构、交互和新版本测量可独立运行。
